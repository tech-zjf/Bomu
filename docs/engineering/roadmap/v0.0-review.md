# Bomu v0.0 工程与验收审查

审查时间：2026-10-21  
审查基线：`main` / `2f66c8f` (`docs: record successful macOS CI acceptance`)  
范围：当前 Swift/AppKit 工程结构、播放与持久化边界、并发/资源生命周期、工程文档、定稿 UI token，以及规范 Debug 包的当前桌面状态。

## 结论

工程的核心分层与 v0.0 目标一致，未发现需要立即阻止继续验收的播放生命周期、数据库所有权或模块反向依赖缺陷。当前可确认的代码质量风险集中在少数大型但职责连贯的文件；不建议为了行数拆分。

v0.0 尚不能签收。完整逐页设计比对、完整 VoiceOver 操作顺序、长时间滚动闪烁观察、校准色彩与有效睡眠/唤醒恢复证据仍未完成。现有构建、静态分析、自动化回归和 CI 只能证明其覆盖的代码路径，不能代替这些桌面验收。

## 工程结构与代码质量

- `App` 持有应用级生命周期、播放会话和数据能力；`PlayerFeature` 将意图提交给 `PlayerModel` 并呈现状态；`Playback` 与 `Rendering` 将 SwiftUI 页面隔离在 native 播放适配层之外。
- GRDB 导入仅出现在 `Sources/Persistence/PlaybackHistoryStore.swift`。播放页面和媒体库 UI 不持有数据库库类型。
- libmpv C 接口集中在 `Sources/Playback/MPV` 和 `Sources/Rendering`；UI 不直接持有 mpv 指针。会话、请求和渲染资源有明确所有者。
- `PlaybackState` 使用枚举表达阶段；播放请求 ID、取消和关闭路径在模型/适配边界处理。先前审查和当前代码检索没有发现新的异步资源泄漏或旧请求覆盖新请求问题。
- 可复核的逻辑回归包括：`PlaybackStateTests.testLateEventsCannotReplaceNewFile`、`testStopInvalidatesQueuedEvents`、`testSnapshotCannotReviveEndedPlayback`；`PlayerModelTests.testCancelOpeningRejectsLateEventsAndAllowsAnotherFile`、`testConcurrentShutdownWaitsForOneTeardownWhileHistoryWriteIsSuspended`、`testSavedPlaybackStateFlushesOnShutdownAndReopensFromFreshStore`、`testQueueAdvancesOnlyAfterNaturalEndAndCanRecoverFromFailure`、`testPlaybackProgressCheckpointIsWrittenDuringPlayback`。最新一次 178 项 XCTest 运行记录见工程进度；测试覆盖模型/存储行为，不等同于实际输出设备的音画与睡醒验收。
- 当前 Swift 源码检索没有发现 `TODO`、`FIXME`、`try!`、`as!` 或 `fatalError`。唯一 `@unchecked Sendable` 是缩略图 AVFoundation callback 桥接私有类型；实现用锁保护生成器调用、continuation 和完成标志，并在代码注释中说明合同。它仍应随 AVFoundation 更新保持针对性回归。
- 当前较大的源文件：`PlaybackHistoryStore.swift` 1,524 行、`MediaLibraryView.swift` 779 行、`BMMPVSession.m` 701 行、`PlayerModel.swift` 660 行、`BMVideoSurface.m` 644 行、`MediaLibraryModel.swift` 563 行。存储 actor 聚合迁移、媒体身份、扫描、历史和归档操作，是主要维护性热点；其他文件也需要持续关注职责边界。只有出现独立生命周期、真实复用或可验证测试边界时再拆分。
- 当前工作区在审查前干净，`main` 与 `origin/main` 一致。最新已推送 CI 对应 `2f66c8f`，GitHub Actions run 144 已通过锁定工具链、依赖/许可证检查、148 项 Python 检查、178 项 hostless XCTest、应用构建、静态分析、运行时闭包和原生测试编译。原生播放集成测试在 CI 中仅编译，没有执行。
