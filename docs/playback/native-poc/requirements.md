# 原生播放 POC

## 目标与范围

按照开发定稿的 v0.0 阶段，验证本地文件 → libmpv → AppKit 视频宿主 → SwiftUI 控制层 → 停止和退出的完整路径。先取得真实播放证据，再扩展队列、字幕、媒体库和发行能力。

本次交付支持 macOS 14+、arm64、Swift 6。首轮验证环境为 Xcode 26.1.1 / Swift 6.2.1；播放运行时为固定的 mpv 0.41.0 / FFmpeg 9.0.1。内核使用 OpenGL render API 和 SDR 输出，不宣称原生 HDR 或 Metal 已实现。

## 已实现行为

| 用例 | 当前行为 |
| --- | --- |
| 打开本地文件 | 系统选择面板、⌘O 和系统单文件打开入口最终调用同一个 `PlayerModel.open`；MKV 在应用配置中声明为导入的视频类型；面板依附主窗口，已有 sheet 时不重复创建；只读原文件，不复制、不修改、不转码 |
| 初始化期间切换选择 | 仅提交最后一个选择；初始化期间关闭窗口，先等待初始化返回再释放资源 |
| 播放与暂停 | 播放状态来自内核；快速连续点击保留最新暂停意图，按文件请求与命令编号确认，旧快照不能错误确认新操作 |
| 定位与音量 | 前后 10 秒；时间线拖动结束时提交绝对定位；暂停时定位继续保持暂停；音量范围 0–100 |
| 控制层 | 原生标题栏、中央控制与底部时间线；静止 2.5 秒隐藏，暂停、操作滑块、焦点或悬停控件时保留；支持减少透明度设置 |
| 画面与全屏 | mpv 根据媒体宽高比适配宿主，保留必要黑边；窗口缩放和原生全屏共享同一播放会话 |
| 结束与失败 | 自然结束展示重新播放；损坏或不可达文件显示错误，可重新选择；停止回到启动页 |
| 快速切文件 | mpv playlist entry ID 在适配边界映射到 request ID；旧请求事件不能覆盖新文件状态 |
| 退出 | 先停止事件接收和采样，再释放 render context，最后销毁 mpv handle；退出等待这条链路完成 |

这是一套最小播放界面。字幕/音轨/倍速菜单、多文件队列、目录拖放、断点续播、书签权限、数据库和更新均留在对应版本任务中。

- 真实 libmpv 测试覆盖 H.264、H.265 Main10 SDR、暂停后定位、切换、损坏文件恢复、自然结束、20 次窗口尺寸变化、100 次快速替换，以及加载中退出。

首帧与资源测量的定义、逐次结果和源码/媒体校验记录见 [benchmark.md](benchmark.md) 与 [本机基线 JSON](baseline-2026-10-13.json)。此前未满足窗口可见性检查的运行不计入该基线。

随后实际观察发现纯音频仍保留上一视频画面，说明上述参数断言不足以证明画面正常。已按 `vo-configured` 生命周期在渲染层完整清屏，并追加 clear-only 绘制断言。最终 21:24 运行实际确认音频背景清空、切回视频正常：仍为 29/30 项通过（TS 定位未修复），100 次暂停/恢复和最小化检查通过，持续播放 120.075 秒、3597 个新帧，停止与退出释放通过。修复后另跑的 4 项真实内核回归通过；以媒体矩阵文档中的最终证据为准。

自动集成测试静音运行。进度推进与截图只能证明对应部分，不能替代声音、色准、同步或资源增长验收。用户视频的声音确认也不代表 H.265 和所有音频输出设备均已验收。

## 实现状态与完整链路

当前状态为 **v0.0 最小播放链路已落地，阶段验收进行中**。没有把 v0.0 或 A05 标记为完成。产品规划与验收条件保留在 `player_plan/开发定稿/`；本目录记录本次已实现的范围与证据。

第一轮审查追加了暂停交错复现与修复、音频时钟零提前量配置及提交时序前后测量。最新结果见 [审查跟进](review-follow-up.md)，初始 17:25 基线作为历史对照保留；帧提交校正不能代替扬声器与屏幕之间的实际同步测量。

入口为 `BomuApp`、`OpenMediaPanel`，输出为 `PlaybackState`、真实 AppKit 视频画面及系统音频。具体边界与取舍见 [technical-design.md](technical-design.md)，端到端流程见 [flow.md](flow.md)，依赖准备与发行限制见 [libmpv 说明](../../../ThirdParty/libmpv/README.md)。
