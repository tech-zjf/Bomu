# 媒体库首页与侧栏

## 结构

`MainWindowView` 持有主窗口页面路由。`MediaLibraryView` 展示媒体库；`PlayerScreen` 持续挂载在同一窗口中，保留现有 `PlayerModel`、AppKit 视频宿主和原生播放会话。选择已索引媒体后切到播放页；返回媒体库时继续播放，并显示当前播放栏。停止播放后回到媒体库。

侧栏提供首页、视频库、文件夹、收藏和搜索入口；设置仍使用系统设置场景。选择文件夹后启动 `MediaLibraryScanner`，进度栏展示发现数、索引数和最多五个最近发现的文件名，也可取消扫描；文件名预览在扫描结束后清除，索引完成的项目由数据库快照发布。来源在线状态根据已挂载卷 UUID 推导，媒体文件使用身份层保存的卷相对路径定位。主导航留在 `MediaLibraryView.swift`；拥有缩略图加载状态的卡片、列表行和两者共用的元数据摘要分别位于 `MediaLibraryCard.swift`、`MediaLibraryListRow.swift` 与 `MediaLibraryPresentation.swift`。卡片和列表行单击只更新媒体库模型中的选中媒体；独立播放按钮才创建播放请求，选中项在库刷新和播放器/浏览切换时保留。

## 数据流

`AppLifecycle` 将现有 `PlaybackHistoryStore` 同时交给播放器、自动核对协调器和 `MediaLibraryModel`，并持有一个 `MediaThumbnailCache`。模型在单个 SQLite 读事务中读取来源根目录、媒体条目和目录成员关系，避免扫描写入穿插读取时发布互相矛盾的快照；全库视图按稳定媒体 ID 去重，保留来源和路径查询的首次顺序。同一文件属于多个来源时优先选当前仍存在的成员记录；状态相同时选最早加入的记录，避免某个旧来源的删除标记把另一个来源中的有效文件隐藏。每个根目录仍保留独立条目用于文件夹页。继续观看读取真实播放进度。最近添加按成员关系中的 `added_at` 排序；该值只在首次加入来源时写入，后续扫描会保留。收藏与已看状态放在独立的 `media_file_preferences` 表中，不和播放进度混为一项。

媒体库显示时，卡片和列表行才请求缩略图和真实媒体属性；离开媒体库后，异步任务会取消。文件路径、内容版本或页面可见性变化会重新识别加载任务，因此来源内移动后不会一直保留旧位置的占位结果。缩略图和元数据探测服务都限制并发，按文件 ID 与内容版本复用有效结果，来源视频保持原样。文件大小、路径和播放进度来自真实文件身份及历史记录；时长、尺寸、编码和音轨由 AVFoundation 探测，失败时显示未知，不根据文件名猜测。

首页、视频库、收藏、已看、继续观看、最近添加和搜索都从 `MediaLibraryModel.availableItems` 派生；它只包含仍被扫描确认存在且所在卷已挂载的媒体。SQLite 快照仍保留缺失成员关系和播放历史，文件重新出现时可以恢复；活动媒体网格不把这些历史行伪装成当前可用媒体。

## 播放与浏览切换

打开媒体只切换 `MainWindowView` 的可见路由。`MediaLibraryView`、`PlayerScreen`、`PlayerModel` 和 AppKit 视频宿主始终由同一个根视图持有；浏览页通过透明度和命中测试隐藏，离开时取消卡片的缩略图/元数据任务，但保留侧栏选项、搜索、筛选、导航和滚动状态。返回按钮只切回浏览并刷新 Now Playing 状态，不停止播放；明确停止后，播放器状态进入 idle，根视图再自动返回媒体库。当前播放栏从同一 `PlayerModel` 读取播放项和暂停状态。

无宿主行为测试覆盖缺失成员过滤；实际窗口走查在屏幕 1 的同一个 Bomu 窗口完成。用完整扫描留下的 60 条历史测试成员确认，Library 只呈现当前存在的媒体，历史数据库记录没有删除；英文界面和选中导航状态也已目视复核。更大窗口尺寸、VoiceOver 和键盘焦点仍待验收。

## 当前边界

文件夹浏览按来源根目录展示在线目录，子目录从已索引媒体的相对路径派生；可逐层进入、通过面包屑返回，并切换网格/列表。空目录不会列出，因为扫描索引只保存媒体文件。搜索在内存中筛选已加载索引，万条命中回归通过；更大规模的数据库查询优化按 C10 的测量结果决定。文件夹重定位与安全书签持久化仍属于 C03 后续工作。收藏、单项已看和手工媒体分类已持久化；批量已看后置。

## 待验证

之后在屏幕 1 的同一个普通 Bomu 窗口中继续检查：真实用户素材缩略图、离线来源提示、子目录返回、密度切换、面包屑、滚动恢复、筛选与页面切换。当前窗口中的彩条封面来自许可测试夹具，不代表最终内容视觉；损坏夹具也只用于错误状态覆盖。

## 文件夹视图职责

来源卡片、离线来源提示、目录卡片/行和面包屑组合放在 `MediaLibraryFolderViews.swift`。这些值视图只依赖目录事实与导航绑定；目录栈、密度、滚动锚点及数据查询仍归 `MediaLibraryView` 所有，避免展示拆分复制业务状态。Xcode 27 app 构建与静态分析通过，内部 DMG 也按当前源文件重建并校验。文件夹的真实视觉、键盘焦点和滚动恢复仍需单窗口验收。
