## 修复与回归

实际观察发现：从视频切到纯音频时，音频参数和 `vo-configured=false` 虽然正确，画面仍显示上一段视频。已修复为权威视频输出状态驱动渲染层完整清屏；四个纯音频用例均取得 clear-only 绘制证据，并实际确认 FLAC 播放显示干净黑色背景、切回视频恢复画面。新增断言防止再次仅凭内核状态计为视觉通过。

最终运行目录为 `.build/benchmarks/20261013-212456/`。使用正式 `PlayerScreen`、`PlayerModel`，窗口保持 960×600 点、临时置顶，全程窗口 ID 为 27969、显示器 ID 为 3（本机外接屏）；内核与 render context 各创建一次，共尝试打开 31 个文件（30 项矩阵加持续播放长片）。没有自动缩放、全屏或跨屏；仅在启动时通过辅助功能置前一次，测试完成关闭自己的窗口。为人工检查，每项完成后统一留出 2 秒画面观察时间。

## 仍需处理

TS 文件可以完整解码，但暂停中精确定位后，时间已推进至 3.262 秒而视频帧未恢复。该问题见 [复现与调查边界](known-issues.md)。下一步先完善定位完成/失败契约和容器索引行为的验证，再继续收尾 v0.0。

本轮静音；用户之前确认的一段视频听感不能扩大为全部音频通过。AppKit 可见性不证明每个物理像素无遮挡；帧提交不等于屏幕扫描或扬声器输出同步。色准、物理音画同步、原生 HDR、GPU 功耗及长期资源测试仍待专门验收。
