## 修复与回归

实际观察发现：从视频切到纯音频时，音频参数和 `vo-configured=false` 虽然正确，画面仍显示上一段视频。已修复为权威视频输出状态驱动渲染层完整清屏；四个纯音频用例均取得 clear-only 绘制证据，并实际确认 FLAC 播放显示干净黑色背景、切回视频恢复画面。新增断言防止再次仅凭内核状态计为视觉通过。

最终运行目录为 `.build/benchmarks/20261013-212456/`。使用正式 `PlayerScreen`、`PlayerModel`，窗口保持 960×600 点、临时置顶，全程窗口 ID 为 27969、显示器 ID 为 3（本机外接屏）；内核与 render context 各创建一次，共尝试打开 31 个文件（30 项矩阵加持续播放长片）。没有自动缩放、全屏或跨屏；仅在启动时通过辅助功能置前一次，测试完成关闭自己的窗口。为人工检查，每项完成后统一留出 2 秒画面观察时间。

## 2026-10-15 锁定运行库复验

Xcode 27.0 / Swift 6.4 / arm64，Screen 1 内建 Retina 显示器 ID 1，一个固定普通窗口、一个正式 `PlayerScreen`/`PlayerModel`/libmpv 会话。A04 媒体矩阵 **30/30 通过**，包括 H.264、HEVC Main10、4K/竖屏/方形、变帧率、音频独立轨、全范围 SDR、无声视频、损坏输入恢复和 MPEG-TS 定位恢复。所有可播放样本均检查解码媒体属性、暂停、绝对定位、恢复后的时间推进与新帧；活动音频输出则按采样率/声道核验。

`20-h264-aac.ts` 通过中点暂停定位并恢复出新帧，关闭了此前的 MPEG-TS 定位问题。`16-invalid.mp4` 与 `30-truncated.mp4` 均按预期拒绝，后续有效样本继续播放。唯一的原生会话只创建一次；单轮暂停/恢复后停止，5.3 秒内帧数、绘制数和状态采样数均无增长；退出后 `coreAlive=false`、`renderContextAlive=false`、`graphicsContextAlive=false`。

单轮连续播放设为 0 秒，因此不构成长时间播放、GPU 功耗或内存泄漏验收。最小化/恢复探针为遵守固定屏幕策略而跳过；这次测试静音，音频参数通过不代表逐项听感。同步素材的提交误差均值约 4.19 ms、无超过 2 ms 的提前提交帧；此指标不等同于物理屏幕与扬声器同步。用户此前对指定 16:9 测试片确认声音正常、同步闪光/提示音确认同步，结论只适用于对应人工验收素材。

完整报告：`.build/benchmarks/20261015-140728/window-lifecycle.json`。此报告运行时窗口固定在显示器 ID 1；未全屏、跨屏或同时打开第二个播放器窗口。

本地可见矩阵仍为静音；用户此前确认的一段视频听感不能扩大为其余素材。AppKit 可见性不证明每个物理像素无遮挡；帧提交不等于屏幕扫描或扬声器输出同步。校准色准、原生 HDR、GPU 功耗及长期资源测试仍需专门验收。
