# 来源增量与恢复：实施边界

2026-10-26 的落实设计，**尚未实现或验收**。当前真实链路仍见 [定期核对实现](../../playback/library/incremental-sync.md)。本文件用于约束下一批代码，不替代 C03 签收。

## 用例与事实源

首版为单用户、离线、非 App Sandbox 应用。用户添加目录、改变递归范围、重试访问或明确选择恢复位置；系统目录事件、挂载变化和定时器只提示重新核对。原始媒体由文件系统拥有，应用只读，不转码、不复制、不移动媒体。

定稿明确允许普通 URL bookmark 用于位置恢复，不要求非沙盒所有目录使用 security-scoped bookmark。bookmark 只提供候选位置，不能证明访问授权、内容相同或本轮枚举完整；不因其解析成功直接更新有效来源。

| 数据 | 现有所有者与身份 | 新能力的约束 |
| --- | --- | --- |
| 来源卷 | `media_sources.volume_id` | 挂载点是当前系统状态，不能把 POSIX 设备号当持久卷身份 |
| 用户选择的目录 | `media_source_roots.id`，唯一 `(volume_id, relative_path)` | 恢复原来源保留 root ID；普通书签由此行拥有，不另建无独立生命周期的实体 |
| 媒体身份 | `media_files.id`，卷内身份、版本及内容指纹 | 同路径替换、跨卷和重复身份继续经过既有解析/冲突规则，不按文件名合并 |
| 来源中的媒体 | `media_source_files` 的 M:N 关系 | 保存成员关系和最近发现事实，重复来源不复制收藏/历史 |
| 目录导航 | `media_source_directories` | 属于来源的已核对目录投影，不把未扫描目录显示为空目录 |
| 扫描运行 | `media_scan_runs` | 保存完成/部分失败/取消及实际扫描范围，保证失败后可核对 |
| 可访问状态 | 运行时文件系统探测结果 | 不在数据库复制瞬时权限或在线布尔值；由同一来源状态供页面和播放入口使用 |

规模沿用当前万条索引验收场景，不引入服务端、消息队列、分片或新的通用资源框架。数据库仍由数据层唯一连接与迁移管理。

## 独立的状态维度

卷在线不等于目录可读。来源可访问状态需明确区分可用、卷离线、权限拒绝、路径不存在、身份冲突，以及其他有类型的访问失败。扫描进行中、取消、部分失败是独立操作状态；不能把取消扫描当成来源离线。

UI 只展示状态、提交重试/选择位置意图。离线、权限失败和无效路径继续展示已有索引、收藏与历史，禁止因探测失败清空库。播放与元数据读取使用同一已确认的来源解析结果；不能让卡片显示可用而底层从另一套路径映射打开文件。

原生错误在文件系统适配边界按错误域和代码分类，保留未知失败；不得靠本地化错误文本匹配权限，也不能把所有失败兜底为 Offline。

## 增量核对的事务范围

当前 `finishScan` 会把**整个来源**中本轮未见成员标为不存在。仅把 FSEvents 接上现有扫描器、改成扫描一个子目录，会错误隐藏其他子目录，必须同时修改模型、查询与调用方。

扫描契约需显式携带完整来源或来源内子树范围。路径比较按组件边界，正确处理根路径、相邻前缀、大小写/卷规则以及 SQL `%`、`_` 字符。被删除的目录应核对仍存在的父目录；不能对不存在的路径执行一次“空成功”然后批量标 missing。

1. 目录事件在窄原生适配层转换为变化提示，保留丢事件、根变动和挂载语义。
2. 协调器去抖并合并重叠子树；变化过宽、丢事件、卷变化、启动和周期恢复执行全来源核对。
3. 每个来源同时最多一轮扫描；后续意图等待旧扫描取消及事务收尾。手动扫描与后台扫描不得竞相完成删除核对。
4. 扫描发现仍渐进写入；只有来源身份/访问有效、对应范围完整枚举且无跳过，才能核对该范围的 missing。
5. 子树核对不得更新“全来源最近成功核对”时间，其他来源及范围外成员不变。跨子树移动由身份解析保持媒体 ID，再更新各范围成员事实。
6. 退出先关闭事件输入，注销/停止事件流，取消定时与扫描任务，等待生产者和事务收尾；不能留下独立后台扫描。

现有 `(source_root_id, last_seen_scan_id)` 索引支撑来源核对；子树筛选还需结合媒体/目录路径。以实际增量查询的 `EXPLAIN QUERY PLAN` 决定是否新增索引，不预先堆叠低选择性索引。

## 恢复位置与身份验证

恢复流程为：选取候选目录 → 完整读取/核对候选及原来源身份 → 展示可核对结果 → 提交事务 → 刷新来源快照/事件订阅。取消、部分枚举、权限失败、错误路径、冲突或验证期间文件变化均保留原 root 和用户事实；不能先改路径再试扫。

同卷移动可以结合既有卷内身份和文件内容事实核对。跨卷恢复必须明确经过内容匹配，不能以相同目录名、文件数量或 bookmark 解析成功为依据。现有大文件指纹为最多 80 KiB 的五段抽样，不能宣称它证明了全文件字节相同；小文件不超过 80 KiB 才是完整读取。实现时须保留这一证据边界，并覆盖含同名不同内容、缺文件、重复匹配和验证中变化的拒绝路径。无法唯一验证的来源保持原状，明确展示冲突，不猜测合并。

root、目录成员、受影响媒体映射及相关用户事实的变更在数据层事务完成。不能绕过现有隐私目录和旧 checkpoint 防护。普通书签是本机定位辅助，不随可移植 JSON 归档作为跨机访问授权恢复。

## 验证清单

- 真实临时目录/SQLite：只变更 A 子树时 B 保持可见；增删、跨子树移动、相邻路径前缀、重叠来源、非递归来源均验证真实可观察结果。
- 事件丢失、根变动、挂载与周期核对回到全来源；取消/异常/重复事件不清空索引，结束后无活动扫描与事件 owner。
- 权限拒绝、路径不存在与卷离线分别呈现；失败时收藏、历史、索引和原文件字节不变。普通目录权限测试不替代 macOS 隐私授权的真机测试。
- 恢复位置匹配/不匹配/部分匹配/冲突/事务失败/取消；恢复原来源保留 root/media ID 和用户事实，错误候选零修改。
- 旧 schema 的书签字段缺省、旧归档不含本机书签、迁移失败保留备份；相关导入、清理、退出调用方一并回归。
- 规范 Debug 单窗口实际添加、后台增删、来源失败与恢复；物理拔插与 macOS 权限恢复单独记录，不用 mock 或临时卷测试冒充。

上述清单目前没有新增通过收据；长时内存测试期间没有修改生产源码或运行额外编译。
